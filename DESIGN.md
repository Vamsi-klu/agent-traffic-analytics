# DESIGN.md · cake's design standard: shadcn/ui components + the Frosting theme

This is the **single design standard** for every cake interface: the home page after install, the dashboard, sessions, replay, settings, and any page added later.
Read this file before you change any interface, follow it, and when you are done pass the three checks in §12.

In one sentence: **every component is shadcn/ui (React + Radix), and every look comes from one set of theme tokens, "Frosting"**. The cartoon feel comes from the mascot Crumb, the illustrations and the theme's uniform thick outline + hard shadow; the component structure stays exactly as shadcn ships it.

- Code: `web/` (Vite + React + TypeScript + Tailwind + shadcn CLI). For a release, `npm run build` compiles it into static files in `web/dist/` that go into cake's package; the Python process only serves static files and JSON. Users never install Node.
- The only implementation of the tokens: `web/src/styles/tokens.css` (variable names follow shadcn). Tailwind only maps them to class names (`@theme` in `web/src/index.css`, which holds no values).
- Components: `web/src/components/ui/` (generated by the shadcn CLI; the Frosting changes are written in the components); cake's own components: `web/src/components/cake/` (built only from ui components and tokens); pages: `web/src/pages/`.
- Component overview: `#/components` (like the shadcn docs: every component and every variant on display).
- Data: pages hold no data. They read cake's JSON API (`/api`) through `web/src/data/` (types, JSON Schemas, and sample answers that only the screenshot and dev servers use); `web/README.md` lists the endpoints.
- Checks: `npm run check:ui` (rules + this file's token table + the `/api` contract), `npm run visual` (screenshots compared pixel by pixel with the baseline).

## 1. Principles

1. **Human or agent at a glance.** The session categories (D39: the three verdicts Human, Agent and Bot, a Human session cake couldn't tell marked thin evidence, an Agent session split into Agent only and Human + agent, and which agent by name) have one set of colors, one set of icons and one set of words across the whole site (§3.1).
2. **The reasons are always visible.** Next to every verdict you can see, or click through to, the four layers of reasons (name, verification, environment, behavior); layers that are off are shown too.
3. **One kind of thing has one look.** A button is shadcn's `Button`, a card is `Card`. A new look can only be a new variant on a component, written into §6 of this file; **pages may not restyle anything on their own** (the check script blocks it).
4. **Cartoon, not childish.** The cartoon comes from Crumb, the illustrations, and the uniform outline and hard shadow; numbers, charts and reasons use normal typography.
5. **Everything local, in plain words.** Fonts, icons and illustrations are all bundled; copy is short, buttons are verbs, nothing is overstated (§2).

### 1.1 Scope: record everything, highlight Agent sessions

Decided by the user on 2026-11-12: 「我们是所有session都记录，也都留着，但是人和AGENT 的SESSION 是我们着重highlight的」 ("We record every session and keep them all, but human-and-agent sessions are the ones we highlight").

- **Record everything, keep everything**: Human, Agent and Bot sessions are all recorded and all kept; by default nothing is deleted by age (0.3.4 `retention_days 0`).
- **Highlight Agent sessions**: an agent from start to finish (Agent only) or a human and an agent taking turns (Human + agent). On every page they come first and stand out most (§6.1). (D39, the user on 11/13: the industry's words, Human / Agent / Unknown / Bot, with Agent split into Agent only and Human + agent, replaced "Human + agent" for the whole group and "Mixed".)
- **Human is the comparison group**: shown normally, not muted. **Bots are not highlighted**: only counted and filterable, muted in lists, kept out of agent charts.
- **Disk**: the budget defaults to 10 GB; at 80% the settings page and the dashboard warn. "Cleanup when the budget is full" is on by default: it deletes down to 90% of the budget, and only the replays of Human sessions with no activity in the last 1 hour (their visits and verdicts stay); Agent sessions and Human ones on thin evidence are never deleted. When it is off and the disk is full, new replays stop being stored, visits and verdicts are still collected, and the session records how many events were dropped. Choosing 90- or 30-day retention also deletes sessions with an agent by age, and the settings page must say so. (As in cake 0.3.4, fce7503)

## 2. Voice and tone

- Short sentences, active voice, second person. Buttons name the action ("Watch them", "Copy", "Delete all data"), never "Submit" or "OK".
- Verdicts are Human / Agent / Bot (an Agent session is Agent only or Human + agent; a Human session cake couldn't tell is marked thin evidence), never "Suspicious" or "Fraud". The model's confidence is phrased "cake thinks", or, on the session page, as the calibrated percent next to the verdict and each layer (§6.4), never as an accuracy figure.
- Empty states say what to do next; errors say what happened and what to do. At most one playful line per screen, and no jokes in numbers or reasons.
- Interface text is in English for now; the sentence for the coding agent can be switched between English and Chinese.
- **Who acted: only these words**: words about verdicts are only Human / Agent / Bot, Agent only / Human + agent, thin evidence, and Unknown only for a stretch or a layer that couldn't tell (plural Humans / Agents); person / people / user are never used for visitors (the user, 11/12: 「都统一成 "HUMAN", "AGENT" 这样区分准一点」 ("Make them all 'HUMAN', 'AGENT'; that tells them apart more precisely")). Examples: "Human + agent sessions", "A human", "Pages humans visit most", "Sessions where an AI agent acted for a human", "Human only". These sentences live in `WORDS` in `web/src/lib/words.ts`; text that comes with the data (session titles, reasons, the coverage table) comes from cake's API and follows the same rule. `npm run check:ui` blocks person / people and "PostHog" in interface text (comments excepted), and also "user" for a visitor in the API samples ("user agent" is fine). Headings and buttons use sentence case.
- **Product name**: publicly it is "AgentCake" (decided 2026-11-12, spelled as one word since that evening; the command and package name is agentcake). The name in the interface comes only from `name` in `agentcake/data/product.json`, which the pages read when they are built (`vite.config.ts` gives it to them as `VITE_PRODUCT_NAME`): the browser title (`%VITE_PRODUCT_NAME%` in `index.html`) and the components (`PRODUCT_NAME` in `src/lib/product.ts`: the top bar, the home page, Crumb's screen-reader name, the error that says cake can't be reached, and the sentences that mention the product in settings and the component overview); components never hard-code it. Text that comes from cake's API (reasons, the coverage table) arrives with the name already in it. Wherever a sentence refers to the product, either use `PRODUCT_NAME` or rephrase it so no name is needed ("Why this verdict", "Decision method", "Classification"). The mascot Crumb and the cake theme stay. Commands in code blocks use the command's name, `agentcake …` (`command` in `agentcake/data/product.json`).

### 3.1 The session categories (the same everywhere)

D39 (the user on 11/13, settled on the words the industry uses, then: no kinds of agent, list them by name): one word each, written once in `agentcake/data/judging.en.json`, which the pages read when they are built (`web/src/lib/taxonomy.ts`) and the API's words use too, so every badge, filter, block and sentence says the same word.

1. **Verdict**, one per session, together every session: Human, Agent, Bot. An Agent session is **Agent only** (an agent from start to finish) or **Human + agent** (a human and an agent took turns; the timeline marks each hand-off). A session cake can't tell (too few actions, a phone or tablet, evidence too weak or pointing both ways) is Human, marked **thin evidence**: its reasons say which (the user, 11/13: 「不要有 unknown 这个分类，我们统一把 unknown 放到 human 里面。然后标记出来就行」 ("No Unknown category: put unknown into Human, and mark it")). A stretch of a session the behavior model couldn't tell is no verdict: it reads Unknown in bars, timelines and the reasons panel's layers. A prefetch that was never shown is no visit and in no category.
2. **Which agent**: the product's or the automation tool's name (Claude in Chrome, Comet, ChatGPT agent, Playwright, Selenium…) and how sure it is, Verified (a signature or a published address range), Likely (the name it gives, or the product's or tool's own traces) or Possible (its behavior alone); **Unnamed** when no name fits (what was seen, such as automation markers that don't show which tool, is in its reasons). What kind of agent it is (an AI in a real browser, an automated browser) is a reason too, never a category (the user, 11/13: 「为啥 playwright、selenium 就不是人操控的？……还是不要有这两个分类」 ("Why wouldn't Playwright and Selenium be run by a human? … rather not have these two categories")).

Every category badge has one shape: a pill with the `--line` frame, a dot with its icon, the word, and its own colours (the user, 11/13: all the labels the same height and look).

A stretch of a session the behavior model couldn't tell (the actor `unsure`) and a layer that couldn't tell read Unknown, with Unknown's look; a session never does.

- The blue / orange pair was tested with the dataviz skill's `validate_palette.js`: everything passes in light and dark (color-blind ΔE 24.7 / 25.8, normal vision 33.6 / 31.6, ≥ 3:1 against the background). Gray is deliberately not a categorical color; it is told apart by texture and dashed lines.
- Text contrast (dataviz `contrast()`): light mode at least 4.55:1 (`--faint-foreground` on `--muted`), badge text 5.26–5.50:1; dark mode at least 5.88:1.
- `--primary` (strawberry pink) is only for the primary button and the mascot, **never for data**. ok / warn / destructive only show system status, never verdicts.

## 4. Fonts

Headings **Fredoka** (`font-heading`, used automatically for h1–h3), body text **Nunito** (`font-sans`), code in monospace. All are SIL OFL 1.1; the files are in `web/src/assets/fonts/` (with OFL.txt), bundled by Vite, never loaded from the internet.

## 5. Shape: the cartoon frame is part of the theme

- Every "framed" component uses the same frame: `border-2 border-line` + `shadow-hard` (large blocks) or `shadow-hard-sm` (buttons, rows), already written into the components themselves (the "Frosting changes" column of the §6 table). **Pages add no further outlines or shadows.**
- Hover: moves 1px up and to the left and the shadow grows; press: moves down and to the right and the shadow disappears (Button, SessionRow).
- Radius: `--radius` 0.875rem; cards `rounded-2xl`, buttons `rounded-lg`, badges / selects / switches `rounded-full`; a checkbox keeps a small square radius (5px), so it never reads as a round pick-one control.

### 6.1 Highlighting Agent sessions

- **Spotlight block** `Spotlight` (`Card highlight`): at the very top of the dashboard. ### 6.4 The replay page

- **One clock, one count**: every moment on the page (the player, the timeline and its hand-off marks, the reasons, the summary, Pages visited, Every action, the server half) counts from the recording's start and is written as the player writes it (`0:47`); the line under the title gives when the session started, how long its recording runs (the player's length, as the session list gives it) and how many pages it went to (the rows of Pages visited).

In "Why this verdict", each layer's badge shows the side its evidence leans to with its percent ("Agent · 99%"; a behavior layer that found a human and an agent taking turns stays "Human + agent · 97%"); a layer that judged nothing (No hit, Off here, too little data) has no percent. No percent shows when the API gives none. The percent is the page's only word on how sure the verdict is: the summary above the layers says who acted when and which layers support the verdict (those whose conclusion is the verdict's), each with the percent its badge shows. A layer's badge is its conclusion; its percent is how sure the layer is of that conclusion and shows only when it agrees with it; a layer less than half sure of its conclusion says Unknown, without a percent, and its first line says its evidence points both ways. A layer lists only its own findings (a name read off a trace in the page shows under Environment, where the trace is), only the ones that fit its conclusion, and a sentence read from two places once (its detail names both). The behavior layer follows the timeline: Human + agent, "A human and an agent took turns.", when the timeline has hand-offs, the verdict's own side when it has none. A Bot whose environment layer found automation says why it is still a Bot.
- **The player** is rrweb-player 2.0.0-alpha.18 (MIT), the copy cake ships in `agentcake/static/`: the pages load `static/rrweb-player.umd.cjs` and `.css` when a replay opens (no npm copy; the dev, screenshot and test servers serve the same two files). Its frame sits on the stage's `--muted`; nothing of its own controller is shown.
- **Chunks**: the player reads the chunks its first moment needs plus the next one, reads each next chunk as playback enters the one before it, and reads every chunk before a moment it jumps to (rrweb rebuilds a page from its last full snapshot), never the whole replay at once. If playback ever gets ahead of the chunks it waits ("Loading next part…") and goes on.
- **The cursor carries the name of who acts** at that moment: the agent's name ("Agent" when it has none), "A human" or "Unknown", in a pill under the pointer in that side's soft colour and text colour (`--agent-soft` / `--agent-foreground`, `--human-soft` / `--human-foreground`, dashed `--unsure-soft`), framed in `--line`; the click ring and the pointer's trail use `--agent` / `--human` / `--unsure`. The pill keeps the interface's size whatever the player's scale. The rules are in `index.css` ("Replay player"), built from the theme with `@apply`; no colour is written there.
- **Who acted, when** under the player: `SessionTimeline` with the playhead; it moves the replay. Under it, each actor's share of the session's actions ("Human 77% · Agent 23% · Unknown 0% of actions"), its `MiniTimeline` in the order they first act on the timeline; "No actions" when there are none. An action is what Every action lists (a click, typing, a scroll) everywhere on the page: the share and the Actions column of Pages visited count the same ones. Two hand-off labels too close to sit side by side take two rows, so each stays readable at 485 px. "Jump to hand-off" (`Button ghost`, only when the session has a hand-off) starts the player `handoff_lead_ms` before the next hand-off (a cake setting that comes with the session, 3 s by default), going round to the first after the last.
- **Pages visited** under it (`SessionPages`, `pages` of `/api/session/<id>`; the user, 11/13: which pages the session went to, the page it came in on and the page it left from): first the entry page and the exit page, then a `Table` with a row per page in the order it opened: when (`Button link` `xs`, like Every action), the path, the time on page, who acted there (`WhoBadge`: Human, Agent, Human + agent, or Unknown when all its actions are stretches cake couldn't tell; a dash for a page without actions) and its actions (`max-md:hidden`). A single-page app's new address is a new page. A row moves the replay to when its page opened and plays from there, as "Jump to hand-off" does; with no replay to move, the rows are plain text.
- **No replay**: the stage says why, with Crumb `sleep`: deleted to make room ("This replay was deleted to free disk space. The verdict and the timeline are still here."), or nothing to replay; there are no controls then and the timeline has no playhead. A replay cut short while the disk was full plays what is left, with an `Alert warn` under it. A replay with no page recorded up to the playhead (no page snapshot before it, as in a recording made without page content) plays the pointer and the clicks on the empty stage, with an `Alert info` under it saying so; the note goes once a page is there. A replay that can't load shows Crumb `oops`, what happened and "Try again".
- **Server half**: a `Table` in a `Card`, one row per page request (time, page, Sec-Fetch site · mode · dest · user, signature, cake.js network match; the Sec-Fetch and signature columns are `max-md:hidden`), the network line above it in server mode, and cake's sentence when there are no rows.
- In **Every action**, each time is a `Button link` `xs` that moves the replay there.

## 11. Accessibility

## 12. The three checks every interface change must pass (also in AGENTS.md)

1. **Rule check** `cd web && npm run check:ui`: pages may not write `<button>`, `<input>`, `<select>`, `<table>` or `<dialog>` directly, no `style=`, no arbitrary Tailwind values (`w-[13px]`), no color literals (`#fff`, `rgb()`, `oklch()`), no Tailwind palette colors (`bg-red-500`), only token classes; cake components allow only data-driven `width` / `left`; the table in §3 of this file must match tokens.css exactly; every sample answer in `web/src/data/fixtures/` matches its JSON Schema and its TypeScript type (`check:schemas`).
2. **Component overview** `#/components`: new components and new variants go here first.
3. **Screenshot diff** `npm run build && npm run visual`: the component overview and 8 pages (the registration card among them), compared pixel by pixel with `web/visual/baseline/` (the dashboard and the session list show cake's own answers on the fixed test library at one fixed moment, `web/src/data/fixtures/library/`; the home page a fresh AgentCake's); it fails if any pixel changed, and the diff images are in `web/visual/diff/`. If the change is intended, run `npm run visual:update` and commit the new baseline together with the change.

Also, every time: look at light, dark and 485 wide (`npm run shots`); copy follows §2; Agent sessions stand out most on the page, bots are muted.

## 13. Don'ts

- Don't style buttons, cards or inputs yourself in a page; don't hard-code colors or sizes; don't use Tailwind palette colors; don't add outlines or shadows in a page.
- Don't invent an "almost the same" color or variant without writing it into this file and the component overview.
- Don't use red/green for human or agent; don't use the brand pink on data; don't give each vendor's agent a color or logo (the avatars in §15 are the exception the user chose: self-drawn blobs, avatar colors never mean a verdict, no vendor logos or brand colors, the name always beside them).
- No blurred shadows, glassmorphism, gradient shading, 3D or plush.
- Don't load fonts, icons, scripts or images from the internet; don't use other companies' illustrations or trademarks; from 21st.dev and the like borrow only the look, and before using their code check the license and write it into §14.
- Don't write "Coming soon"; don't delete sessions by age by default; don't automatically delete sessions with an agent; don't hide human-only sessions; don't highlight bots.
- Don't show visitors' IPs, emails or account ids in the interface; sessions use a short hash.

## 15. Agent avatars (blobs)

Decided on 2026-11-12: the avatars sway gently while idle and look cute; of the three looks tried (Flat, Depth, Cartoon), they are made in Flat. The reference was a screenshot of the x.ai/bot page (a row of flat-colored blobs with white pill eyes): we borrowed only the feel of "flat blobs + swaying while idle" and did not scrape that page; the shapes and the eyes are our own.

- **Shapes**: 8 dessert blobs: `mochi`, `gumdrop`, `macaron`, `donut`, `pudding`, `scoop` (a scoop of ice cream), `cookie` (a cookie with a bite taken out), `dumpling` (a steamed bun). Self-drawn SVG (`web/src/components/cake/avatar.tsx`). The eyes are Crumb's kind: white eyes + ink pupils (not white pill eyes), and a small curved mouth; the outline uses `--cake-outline`, like Crumb.
- **Colors**: 6 avatar color tokens `--avatar-1..6` (the §3 table), flat fills, **for avatars only, never a verdict**, not used in charts, badges or timelines. They stay apart from the verdict colors: with the dataviz method (OKLab ΔE×100, Machado 2009 color-blindness simulation), each avatar color is measured against the solid and the light colors for human / agent / unknown; it needs ≥ 15 for normal vision and ≥ 8 under red-green color blindness, measured once in light and once in dark; `npm run check:ui` recomputes this on every run (now: light ΔE ≥ 15.0, color-blind ≥ 8.0; dark ΔE ≥ 20.7, color-blind ≥ 14.5). Avatars are not guaranteed to stay apart from each other under color blindness; shape and name tell them apart.
- **One fixed avatar per agent**: name → hash → shape + color + rhythm (`avatarOf()`). No hand-kept list: a new agent gets one automatically, and the same name has the same avatar on every page. Different agents may land on the same shape, but the name is always beside it.
- **Decoration only**: the SVG is `aria-hidden` and the name is always written beside it; no vendor logos, brand colors or mascots. Humans and bots have no avatar (bots are not highlighted).
- **Motion**: a gentle sway while idle: rocking ±4° side to side, bobbing up and down, a little squash and stretch, one cycle every 2.1–3.2 seconds; each avatar's rhythm and starting point are offset (`data-phase` 0–5), so a row of avatars never moves in step; a blink every 4.4–6.6 seconds. Crumb's idle poses sway and blink the same way (§7). Under `prefers-reduced-motion` nothing moves (the global rule in `index.css`).
- **Used in**: session rows and compact rows (before the name, after the Agent session's Crumb marker; an unnamed agent has none), the y-axis of the dashboard's "Agents that visited" (`AgentTick`: avatar + name; a long name wraps to two lines, the whole name on hover), the agent tag on the replay page title (`AgentTag`), and the last block of the component overview. Not used for chart data colors, the reasons panel or table numbers.
- **Size**: 20px in rows (as tall as the name, so rows don't get taller), 16px in tags, 20px on chart y-axes, 56px in the component overview.
